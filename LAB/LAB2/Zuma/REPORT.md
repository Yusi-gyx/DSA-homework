### 代码01

1. **最严重错误类型**：Runtime Error。
2. **原因**：`play`在消除后直接调用`play(left - 1)`。如果从下标0开始消除，就会调用`play(-1)`，函数开头的`a.at(rank)`随即越界，抛出`std::out_of_range`。
3. **发现方法**：跑样例时遇到越界，再读代码定位到递归调用。
4. **测例构造**：让序列头部形成三个同色珠并消除。

**测例**

```text
AA
1
0 A
```

### 代码02

1. **最严重错误类型**：Runtime Error。
2. **原因**：从头部消除时，`left`和`next`都是0。如果整个序列被消空，接着调用`play(0)`时，`a.at(0)`就会越界。
3. **发现方法**：对拍。生成器会生成把序列消空的测例。
4. **测例构造**：用一次消除把整个序列清空。

**测例**

```text
AA
1
0 A
```

### 代码03

1. **最严重错误类型**：Time Limit Exceeded。
2. **原因**：`std::string::insert`和`erase`每次最多移动$O(n)$个字符，总复杂度为$O(nm)$。当$n=m=5\times10^5$时，该测例约需移动$3.75\times10^{11}$字节，超过了1.5秒的时限。
3. **发现方法**：先分析复杂度，再用`-O2`跑最大规模的测例，本地耗时约5.0秒。
4. **测例构造**：用一个长初始串，在头部交替插入两种颜色。这样每次都要移动整串，而且不会发生消除。

**测例**

初始串为`AABB`重复125000次。将`0 C`、`0 D`这组操作重复250000次，共500000次操作。期望输出为$(\text{DC})^{250000}(\text{AABB})^{125000}$。

### 代码04

1. **最严重错误类型**：Wrong Answer。
2. **原因**：左扫描结束后漏了`left += 1`，把左边一颗异色珠子也算进了同色块。`size = right - left`因此多算了1，`a.erase(left, size)`会多删一颗珠子。
3. **发现方法**：对拍发现输出不对，再用gdb检查`a.erase`处的变量。
4. **测例构造**：让两颗相邻的同色珠左边紧挨一颗异色珠，检查程序会不会误消除。

**测例**

```text
AB
1
2 B
```

### 代码05

1. **最严重错误类型**：Wrong Answer。
2. **原因**：`cin >> a`会跳过空行。初始序列为空时，它会把下一行的操作数读进字符串，后面的输入也跟着错位。
3. **发现方法**：对拍。
4. **测例构造**：把初始序列留空，再插入一颗珠子。

**测例**

```text

1
0 A
```

### 代码06

1. **最严重错误类型**：Wrong Answer（越界写入仍落在`p`数组内部）。
2. **原因**：06没有用`p2a()`和`a2p()`重分块。每块最多能放4096颗珠子，插入超过容量后会覆盖相邻块的数据，`p2a()`拼出的序列就错了。
3. **发现方法**：对拍后和后续版本比较，再打印中间变量。
4. **测例构造**：从两个块开始，在同一块里不断插入珠子。让珠子一直留在块内，直到超过容量。

**测例**

初始串由`AB`重复1024次再接一个`A`组成。先将`0 B`和`0 A`交替执行1024组，最后再执行一次`0 B`，共2049次操作。

### 代码07

1. **最严重错误类型**：Runtime Error。
2. **原因**：左扫描跨块时只跳一次（`if`应为`while`）。如果跳到空块，`l.second`仍是-1，接下来的`get(l)`会越界读到上一块末尾的旧数据。如果读到的颜色相同，消除区间就会算大，随后`plen[l.first]`被赋上由-1转成的`size_t`值，`p2a()`里的`memcpy`因此崩溃。
3. **发现方法**：随机对拍没找到错例。询问大模型后，定向构造测例并打印中间变量，发现`plen[0]`变成了`SIZE_MAX`。
4. **测例构造**：先插入到触发重分块，再用连锁消除留下空块，最后触发一次跨空块的左扫描。

**测例**

初始串为`AABB`重复1024次。先把`0 B`、`0 B`、`0 A`、`0 A`这组操作重复512次，再执行`3070 B`和`0 B`，共2050次操作。

### 代码08

4. **测例构造**：让中间一段消除后，两侧接起来还能再消一次。

**测例**

### 代码09

1. **最严重错误类型**：Runtime Error。
2. **原因**：09缺少`if (l.first == r.first)`分支，块内消除也走了跨块逻辑。程序先把左块截断，再用`len = plen[r.first] - r.second`算右侧剩余长度。两个下标指向同一块时，这里会读到刚改过的块长，算出负数。负数赋给`size_t`类型的`plen`元素后变成很大的值，`p2a()`调用`memcpy`时崩溃。
3. **发现方法**：先对拍，再用gdb定位。
4. **测例构造**：在一个块中间触发消除，让块的两端都有珠子留下来。

**测例**

```text
ABBA
1
2 B
```

### 代码10

2. **原因**：跨块消除时，清零中间块的循环从`l.first`开始，连左边界所在块也清零了。起点应该是`l.first + 1`。
3. **发现方法**：对拍后打印中间变量。
4. **测例构造**：先消除序列末尾的一段，再插入一颗珠子，检查刚才留下的珠子是否还在。

**测例**

```text
BAA
2

1 C
```

### 3. gdb调试、中间变量和错例化简

#### 3.1 代码04

用`04.in`运行，在`04.cpp:17`的`a.erase(left, size)`处下断点。左扫描结束后，`a`是`ABB`，同色段本应是`left = 1, size = 2`，实际却是`left = 0, size = 3`。少了`left += 1`，最左边的`A`也被算进了消除区间。这个错例比较容易构造，也方便调试。
